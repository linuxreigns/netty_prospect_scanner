## 2) Estado funcional por módulo

### 2.1 API principal (`app/main.py`)
Routers registrados:
- `routes_scan`
- `routes_dashboard`
- `routes_export`
- `routes_discovery`
- `routes_ai`
- `routes_pipeline`

### 2.2 Scanner (`app/scanner/`)
- `crawler.py`:
  - escaneo por lote asíncrono con `httpx`
  - delay y concurrencia configurable
  - respeto de robots opcional
  - fallback Playwright cuando HTML insuficiente
  - **mitigación SSRF** (bloquea localhost/redes privadas, etc.)
- `detector.py` + `fingerprints.py`:
  - detección de CMS/eCommerce/frontend
  - detección de señales comerciales (chatbot, WhatsApp, formulario, redes, contacto)
- `playwright_fallback.py`: render JS controlado
- `robots.py`: lectura de robots.txt

### 2.3 Scoring (`app/scoring/`)
- `score_engine.py`:
  - Netty Fit Score [0..100]
  - clasificación:
    - 80–100 Caliente
    - 60–79 Bueno
    - 40–59 Medio
    - 0–39 Bajo
  - regla de sitio caído/inaccesible (cap bajo)
- `sectors.py`: rubros de alta demanda

### 2.4 Persistencia (`app/database.py`, `app/models.py`)
- Modelo `Prospect` con `domain` único (deduplicación/upsert en rutas).
- Timestamps en UTC timezone-aware (corrección aplicada).

### 2.5 Discovery (`app/discovery/`)
- `providers.py`: arquitectura enchufable
  - `LocalCatalogProvider`
  - `NullWebProvider` (placeholder futuro)
- `service.py`: agregación + deduplicado
- Catálogo local: `data/discovery_catalog.csv`

### 2.6 IA comercial (`app/ai/`)
- `commercial_analysis.py`: integración OpenAI-compatible
  - soporta `AI_PROVIDER=openai|deepseek`
  - si no hay config retorna fallback seguro
  - **enforcement HTTPS** para `AI_BASE_URL`
- `prompts.py`: prompt comercial en español

### 2.7 Exportadores (`app/exporters/`)
- CSV, XLSX, PDF summary
- rutas API para campañas y listas de ventas

### 2.8 Pipeline comercial (`app/api/routes_pipeline.py`)
- Sync: `POST /pipeline/discover-scan-export`
- Async: `POST /pipeline/discover-scan-export/async`
- Polling: `GET /pipeline/jobs/{job_id}` y `GET /pipeline/jobs`
- Export dual hot leads: CSV + XLSX
- **límite/poda de jobs en memoria** para evitar crecimiento indefinido

### 2.9 Dashboard (`dashboard/streamlit_app.py`)
- métricas generales
- filtros de prospectos
- detalle
- botones de export
- ejecución pipeline sync/async + consulta de job

## 3) Seguridad (estado actual)

### Aplicado
1. **SSRF guard** en scanner:
   - bloqueo de localhost/loopback/redes privadas/link-local/reservadas.
2. **Ruta CSV restringida**:
   - solo `.csv`
   - solo dentro de `data/`
3. **IA por HTTPS**:
   - `AI_BASE_URL` HTTP es rechazado
4. **Poda de jobs async**:
   - límite en memoria para reducir superficie DoS lógico
5. **Secret scanning**:
   - gitleaks en pre-commit y CI

- `AGENTS.md` contiene reglas duras de operación/desarrollo y seguridad.
